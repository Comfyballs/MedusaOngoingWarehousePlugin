# `order.canceled` Subscriber Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Medusa subscriber on the `order.canceled` event that routes every `OngoingOrderSync` row of the cancelled order through the idempotent `cancelOngoingOrderWorkflow` workflow, never throwing.

**Architecture:** A single file `src/subscribers/order-canceled.ts` exporting a default async handler and a named `config`. The handler re-queries sync rows from the `{ id }` payload via the `ongoing` module service (`listOngoingOrderSyncs({ medusa_order_id })`), then runs `cancelOngoingOrderWorkflow` (#28) once per row. `cancelOngoingOrderWorkflow` owns idempotency and the `cancellable_status_codes` gate, so the subscriber loops blindly. The whole body is wrapped in try/catch so it logs and returns instead of throwing — converging with the provider's `cancelFulfillment` (#22) path, which routes to the same workflow.

**Tech Stack:** Medusa v2.16.0 (`@medusajs/framework`), TypeScript 5.6 (Node16 module resolution), yarn 4.6, Jest + `@swc/jest` for unit tests (already wired: `jest.config.js`, `yarn test`).

## Global Constraints

- Medusa version floor: **2.16.0** (all `@medusajs/*` pinned to 2.16.0).
- Package manager: **yarn 4.6.0**. Node **>= 20**.
- Module id is `"ongoing"` (camelCase, never dashes); import the constant `ONGOING_MODULE` from `src/modules/ongoing/index.ts`.
- Subscribers **never throw** (log + record error), are **idempotent**, and **re-query** full data from the `{ id }`-style event payload (spec §8).
- Event name is **`order.canceled`** — single-L (spec §8; verified against 2.16.0 `OrderWorkflowEvents.CANCELED`). Payload is `{ id: string }` only.
- Plugin build output is `.medusa/server`; verify the plugin compiles with **`yarn build`**.
- Tests are **pure unit tests** (mock the module service + the workflow); there is no local Postgres/Medusa instance wired in this plugin.

Create `src/subscribers/order-canceled.ts`:
```ts
import { SubscriberArgs, type SubscriberConfig } from "@medusajs/framework"
import { ONGOING_MODULE } from "../modules/ongoing"
import { cancelOngoingOrderWorkflow } from "../workflows/cancel-ongoing-order"

type OrderSyncRow = {
  id: string
  ongoing_order_number: string
  medusa_order_id: string
  medusa_fulfillment_id?: string
}

function mapRowToInput(orderId: string, row: OrderSyncRow) {
  return {
    medusa_order_id: orderId,
    medusa_fulfillment_id: row.medusa_fulfillment_id ?? undefined,
    ongoing_order_number: row.ongoing_order_number,
  }
}

export default async function orderCanceledHandler({
  event: { data },
  container,
}: SubscriberArgs<{ id: string }>): Promise<void> {
  const logger = container.resolve("logger")
  const orderId = data.id

  let rows: OrderSyncRow[]
  try {
    const ongoingService = container.resolve(ONGOING_MODULE)
    rows = await ongoingService.listOngoingOrderSyncs(
      { medusa_order_id: orderId },
      { select: ["id", "ongoing_order_number", "medusa_fulfillment_id"] }
    )
  } catch (error) {
    logger.error(
      `[ongoing] order.canceled: failed to load sync rows for order ${orderId}: ${
        (error as Error).message
      }`
    )
    return
  }

  if (!rows?.length) {
    logger.info(
      `[ongoing] order.canceled: no Ongoing sync rows for order ${orderId}, nothing to cancel`
    )
    return
  }

  // Cancel every Ongoing order tied to this Medusa order. The workflow is
  // status-gated and idempotent, so a per-row no-op is safe and expected.
  for (const row of rows) {
    try {
      await cancelOngoingOrderWorkflow(container).run({
        input: mapRowToInput(orderId, row),
      })
    } catch (error) {
      logger.error(
        `[ongoing] order.canceled: cancelOngoingOrderWorkflow failed for ${row.ongoing_order_number} (order ${orderId}): ${
          (error as Error).message
        }`
      )
      // Continue with the remaining rows; never throw from a subscriber.
    }
  }
}

export const config: SubscriberConfig = {
  event: "order.canceled",
}
```
